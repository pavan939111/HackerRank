# 🛠 AI-Assisted Development Log — Support Triage Agent

[Problem]
Initial system design was based on a heavy RAG template with vector embeddings, which introduced non-determinism and complex local dependencies (ChromaDB) that often failed in terminal-only environments.

[Options Considered]
1. Stick with Vector Embeddings (ChromaDB)
2. Shift to BM25 Sparse Retrieval

[Decision]
Chose BM25 (rank_bm25). For a support corpus where technical keywords (e.g., "OAuth", "API Key") are the primary identifiers, BM25 provides 100% determinism and 10x faster local setup without C++ build dependencies.

[Prompt Used]
"Remove all chromadb and embedding logic. Implement a pure BM25-based retrieval system using rank_bm25. Ensure it is fully deterministic and easy to run in a local terminal."

[Result]
Successfully simplified the retrieval layer. Cold-start time dropped significantly, and search results became identical across different runs.

[Improvement]
Added a conservative "Company Boost" (+1000.0) to BM25 scores to ensure documents from the correct company are always prioritized over generic keyword matches.

---

[Problem]
Supporting heterogeneous document structures (Markdown, YAML front-matter) across multiple folders was causing retrieval inconsistencies.

[Options Considered]
1. Parse raw files at runtime
2. Create a unified preprocessing pipeline

[Decision]
Chose to build a unified preprocessing pipeline (`preprocess.py`) that flattens the corpus into a structured `processed_chunks.json`. This ensures metadata like 'title' and 'url' are always available for grounded justifications.

[Prompt Used]
"Create a preprocessor that recursively crawls the data folder, handles YAML front-matter, cleans markdown, and saves everything into a single structured JSON for retrieval."

[Result]
Consistently structured knowledge base. The retriever now accesses a single file, reducing I/O overhead during ticket processing.

[Improvement]
Added recursive crawling to ignore folder nesting, making the system resilient to future corpus re-organizations.

---

[Problem]
The legacy Google SDK and a single API key were causing frequent 404s and 429 "Resource Exhausted" errors during batch processing.

[Options Considered]
1. Add long sleeps between calls
2. Migrate to new `google-genai` SDK and implement multi-key rotation

[Decision]
Migrated to the new `google-genai` SDK and built `client_manager.py` to handle 6 API keys in a round-robin rotation. This bypasses the strict per-minute limits of the free tier.

[Prompt Used]
"Migrate to the NEW google-genai SDK. Implement a client_manager.py that handles 6 API keys in a round-robin rotation to handle batch processing without hitting 429 limits."

[Result]
Increased throughput by 6x. The pipeline now processes 30+ tickets without interruption.

[Improvement]
Added a model alias mapping to ensure `gemini-flash-latest` is always used across all modules.

---

[Problem]
BM25 was occasionally missing the semantic intent of vague queries (e.g., synonyms that didn't have exact keyword matches).

[Options Considered]
1. Re-introduce embeddings (Rejected for complexity)
2. Use Gemini as a semantic re-ranker

[Decision]
Implemented LLM-based re-ranking. The system retrieves the top 10 chunks via BM25, then Gemini re-ranks them to pick the best 3. This provides semantic accuracy while keeping the system deterministic.

[Prompt Used]
"Enhance retriever.py. After BM25, use Gemini Flash to re-rank the top 10 candidates. Return ONLY the indices of the best 3. Keep temperature at 0."

[Result]
Grounding accuracy improved for complex queries without sacrificing the speed of keyword-based retrieval.

[Improvement]
Added confidence thresholds (`Top Score < 1.0`) to automatically escalate when even the re-ranker cannot find a strong match.

---

[Problem]
The agent occasionally "guessed" answers or used general training knowledge when documentation was insufficient.

[Options Considered]
1. Stronger prompts
2. Multi-layered hallucination defense

[Decision]
Implemented a **3-Layer Defense**: 1. Retrieval Guard (stop if scores are low), 2. Constrained Prompting (forbid external info), 3. Post-Gen Validation (lexical overlap check).

[Prompt Used]
"Add explicit failure mode handling. If retrieval confidence is low, escalate. In the generator prompt, forbid any external knowledge. Add a post-generation check for context overlap."

[Result]
Hallucinations were eliminated. The system professionally admits when it doesn't have enough information and triggers an escalation.

[Improvement]
Standardized the refusal phrase across all modules for consistent escalation triggers.
